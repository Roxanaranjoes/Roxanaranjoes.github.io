Protect what someone wants to say

An unstable connection can trigger retries and delayed confirmations. The priority is to preserve the conversation and distinguish a pending message from a saved one.

Illustrative specification example

Repeating the same send saves one message. After a reload or network recovery, the history remains available.

Confirm, persist, and recover

Each send carries an identifier unique to its sender. The server returns the saved record; HTTP retrieves updates and history when the connection returns.

Implemented decision

Confirmation depends on persistence. A retry with the same identifier returns the existing message.
