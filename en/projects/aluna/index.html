Problem & context

Aluna is a collaborative academic project exploring space automation at RIWI. The team's architecture connects devices through MQTT and exposes state and events through REST and SSE. PostgreSQL and Prisma organize users, zones, and reservations; MongoDB stores telemetry and reports.

My contribution

I contributed to the backend through MongoDB telemetry contracts and endpoints, on-demand energy estimates, and shared CORS utilities for the APIs. My commits support these contributions. The IoT architecture and interfaces are part of the team's work.

01

Readings that can be queried

The endpoints support recording temperature, humidity, and relay state, and querying readings by device and time range. One contract organizes the data the backend stores and returns.

02

Request an energy estimate

A request to the backend generates and stores a report from relay readings. The result retains the assumed interval and power rating to explain the consumption estimate.

03

Devices within a space

The team project relates zones, devices, and reservations. MQTT carries IoT messages and SSE exposes events to the client, while the APIs support querying state and sending light and fan commands.

01

Align the telemetry contract

I refactored types and endpoints around a telemetry collection with device identifiers, readings, relay state, and timestamps. Input validates required fields, while queries apply filters and limits.

02

Make assumptions explicit

The calculation converts the count of relay-ON readings into minutes and then kWh using a fixed interval and an assumed power rating. The report persists these parameters: it is an estimate rather than an electrical measurement.

03

Share responses across APIs

I centralized CORS header construction and OPTIONS preflight responses. The utilities are reused in middleware and handlers, including SSE events and error responses, reducing duplicated code.
